Elite Event Hub · Design System

Everything orbits the event.

ORBIT is a spatial operating system for event management. It replaces the current interface's flat grid of equal-weight cards with a model where distance means relevance, gold means one thing, and every number knows how important it is.

Dark-first Laravel · Livewire · Alpine WCAG AA Token-driven
00 · The Concept

Five laws

Every decision in this system traces back to one of these. If a new screen breaks one, the screen is wrong — not the law.

01

One light source

Gold is a star, not a paint. It appears on the primary action, the current position, and the single number that matters. Nothing else. Today gold is on ten things per screen, which means it's on none.

02

Distance is relevance

The event sits at the core. Inner orbit = things that change today (Tasks, Budget, Agenda, Suppliers). Outer orbit = structure that rarely moves (Contract, Documents, Settings). A 20-item flat sidebar becomes two rings.

03

Depth by atmosphere

No drop shadows in dark mode — they read as smudges. Depth comes from five surface levels, hairline rim-lights on top edges, and soft radial glows. Exactly five. Never a sixth.

04

Numbers are typography

Every figure uses a monospaced, tabular-numeral face. Columns align. JD 214,498 reads as money, not as a word. This alone makes the Budget screen 40% more legible.

05

Stillness is a feature

Motion is reserved for state change and live risk. A pulsing dot means something is genuinely overdue right now. If everything animates, an event manager stops reading the screen — and this is an interface people stare at for eleven hours during load-in.

01 · Diagnosis

What the current build gets wrong

Direct read of your screenshots. Each problem maps to a fix in this system.

Gold is everywhere
Buttons, borders, rings, icons, headings, badges — all gold. No visual priority survives.
Fix → Gold budget: max 3 gold elements per viewport. Everything else monochrome + signal colors.
Every card weighs the same
Budget Overview, Attendee Overview, Supplier Status, Approvals — identical containers, identical weight.
Fix → A four-step gravity scale: hero primary secondary ambient.
The module rail is a 20-item wall
Overview → Settings in one undifferentiated list. Scanning cost is high, every trip.
Fix → Two orbit rings — Live (7 daily modules) and Structure (collapsed by default).
Dark chrome, light body, no bridge
Navy header slabs sit on a pale gray canvas. The seam is jarring and the header reads as an ad banner.
Fix → One coherent surface stack per theme. Dark for operations, light for planning — never both at once.
Numbers set in the UI face

Fix → A dedicated data typeface with tabular numerals across every figure in the product.
Donut charts for two-value splits
Spent / Committed / Remaining as a ring you have to decode against a legend.
Fix → Segmented linear meters. Rings are reserved for single-value health only.

05 · Foundations

Motion

Three curves, three durations. Anything else is decoration and decoration costs attention.

140ms · ease-out
Response

Hover, focus, press. Must feel instant — the user already knows what will happen.

240ms · ease-in-out
Transition

Panels, drawers, tab switches, theme flip. Long enough to follow, short enough not to wait.

480ms · ease-orbit
Arrival

Ring fills, meter growth, orbit node selection. A slight overshoot that makes data feel like it landed.

The one exception. Two elements are allowed to loop forever: the overdue pulse and the live-phase breathe. Both mean "this is happening right now." Everything else is triggered. Respect prefers-reduced-motion — the system disables both under it.

Tokens are plain CSS custom properties, so they work with or without Tailwind. Below is the wiring for a Livewire 3 + Alpine stack.

1 · Token file resources/css/orbit-tokens.css

/* Import once in app.css, before Tailwind's utilities. */ @import './orbit-tokens.css'; /* Then Tailwind reads them as theme values — no duplication. */ @theme { --color-void: var(--void); --color-hull: var(--hull); --color-plate: var(--plate); --color-deck: var(--deck); --color-rim: var(--rim); --color-ink: var(--ink); --color-solar: var(--solar); --color-vital: var(--vital); --color-critical: var(--critical); --font-display: 'Instrument Serif', serif; --font-sans: 'Inter', sans-serif; --font-mono: 'JetBrains Mono', monospace; --radius-md: 14px; --radius-lg: 20px; }

5 · Rules for contributors

Do
  • → Wrap every figure in .o-num or a metric class.
  • → Give exactly one card per screen data-gravity="hero".
  • → Derive status colour from the Tone enum, server-side.
  • → Use o-meter for splits, o-ring for single values.
  • → Write empty states that teach the concept, not "No data".
Don't
  • → Add a sixth surface level. Restructure instead.
  • → Put gold on more than three elements in a viewport.
  • → Use a signal colour decoratively. Colour means state.
  • → Introduce a new border-radius or shadow value.
  • → Ship a donut chart. Ever.
16 · Build

Migration order

Do not rebuild screen by screen — you'll ship two design languages at once. Go bottom-up so every screen improves the day the layer beneath it lands.

Phase 1 · Tokens & type ~2 days
Drop in orbit-tokens.css, load the three fonts, replace every hard-coded hex and font-size with a variable. Nothing looks redesigned yet, but the whole app quietly becomes consistent and theme-switchable.
Phase 2 · Primitives ~4 days
Buttons, badges, cards, inputs, tables, rings, meters as Blade components. Find-and-replace across existing views. This is where the biggest visible jump happens for the least work.
Phase 3 · Navigation ~3 days
Two-ring module list, compact rail, ⌘K palette. Retire the 20-item flat sidebar. Ship the radial orbit as the ⌘J overlay first — lower risk than putting it on a live dashboard.
Phase 4 · Screen recomposition ~2 weeks
Command Center → Event Hub → Budget → the list modules (Venue, Supplier, Attendee share one template) → documents. Apply the gravity scale, cut cards that don't earn their place.
Phase 5 · Orbit as home ~1 week
Radial navigation on the Command Center, live badge counts, motion polish, reduced-motion audit, full WCAG AA contrast pass on both themes.
One warning. The single riskiest change is retiring the 20-item sidebar. Ship the two-ring version behind a feature flag for your own team for a week before it reaches clients — muscle memory is real, and the outer ring needs to collapse to exactly the right seven modules for how your managers actually work. Watch which outer-orbit items get expanded most and promote them.
